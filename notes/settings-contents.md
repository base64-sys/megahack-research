## Applying function (how a key reaches code)

The registry is keyed by hackpro::Tag (uint64), not by name. The name-to-tag
join happens at runtime via hackpro::extensions::tagFor (0x180072DF0), which
looks the name up in the registry's string-keyed FNV-1a-64 map (container at
registry + 0x130). intern (0x18007C700) inserts (tag, name) pairs during
config load (0x18008B780). The code itself calls the typed accessors with
compile-time tag constants — scripts/settings_index.py recovers 184 distinct tags
read through six accessors (getConfigVar<bool/flag/scalar/int/string/Bytes>).

Consequence: the applying function for a given name cannot be stated from
static analysis alone, because the name-to-tag map is built at runtime. The 184
code-read tags are the universe of settings the code actually touches; the 202 keys
above are the universe the user's install stores. The intersection is not
recoverable without executing tagFor (or interning) against this install's
hackpro.json.
